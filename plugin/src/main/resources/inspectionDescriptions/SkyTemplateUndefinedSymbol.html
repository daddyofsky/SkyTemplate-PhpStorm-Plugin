Reports SkyTemplate constructs whose PHP-symbol reference cannot be resolved by PhpStorm's index — typos like a doubled letter in a function name, deleted helpers still referenced from a template, or class names the project never autoloads.

Covers the same surfaces as Find Usages / Go to Definition for SkyTemplate constructs:

  • Function calls in expression contexts: {=foo()}, {?foo()}, {if foo()}, {var|foo}, …
  • Static method calls: {=Cls::method()}, {var|Cls::method}
  • Class references: the Cls portion of the above
  • Global / namespaced constants: {c.NAME}
  • Class constants: {c.Cls::CONST}

Plain variable references ({var}, {var.field}) carry no resolvable reference and are intentionally left untouched.

Severity: WARNING (not ERROR). PHP allows runtime-registered functions, autoloaders, eval(...)-defined globals, and framework magic methods, so a name absent from the static index can still exist at runtime. The inspection prefers warning over error to avoid false alarms in those scenarios.

Namespace handling. Resolution chain (matches Find Usages / Ctrl+Click): useClass alias expansion, then the configured project namespace prefix, then the global namespace, finally a simple- name fallback across all namespaces. A symbol that resolves under any of those is not reported. Configure the namespace and useClass list in Settings → Tools → SkyTemplate.

Example that triggers:

{=getKakaoLogginUrl()}    {* doubled g — meant getKakaoLoginUrl *}
{=Util::removed()}        {* method removed but template still uses it *}
{c.MISSING_CONST}         {* constant deleted *}

Runs in *.sky files (this inspection) and in HTML host files (via the companion annotator). Honours the master Enable SkyTemplate support toggle.

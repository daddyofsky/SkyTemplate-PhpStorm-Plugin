Reports problems with named arguments in SkyTemplate calls. Three rules:
  • Unknown parameter name — the callee does not declare a parameter by that name. 
    function helper(string $name) {}
{=helper(typo: 1)}             {* `typo` is not a parameter *}
    Severity: WARNING. A poly-variant resolution may have candidates that accept the name; variadic functions (...$rest) accept any name at runtime — both pass silently. This rule is therefore deliberately lenient.
  • Duplicate named argument — the same parameter name appears twice in the same call. 
    {=helper(a: 1, a: 2)}          {* PHP 8 fatal at runtime *}
    Severity: ERROR. PHP 8 raises Error: Named parameter $a overwrites previous argument.
  • Positional argument after named — a positional argument appears once a named argument has been passed. 
    {=helper(name: 1, 2)}          {* PHP 8 fatal at runtime *}
    Severity: ERROR. PHP 8 raises Error: Cannot use positional argument after named argument.

Pipe form. SkyTemplate's pipe-filter syntax uses = instead of : for named args: {var|fn=mode=daily, count=3}. Comparison expressions ({x|fn=count==2}) are not treated as named args (the == guard).

The ## placeholder in pipe filters is the pipe-input slot, not a user argument — it neither acts as a named marker for rule e nor counts toward duplicate detection.

Call shapes covered:

  • Paren calls: {=foo(name: 1)}
  • Static methods: {=Cls::method(value: 1)}
  • Pipe filters: {var|fn=mode=daily}

Object method calls ({=user.method(...)}) require variable type inference and are out of scope.
